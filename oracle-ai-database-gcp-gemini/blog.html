Develop A2A Agentic AI with Oracle AI Database and Gemini Enterprise

Recreate a multi-agent supply-chain demo on Oracle AI Database@Google Cloud: identify stockout risk, traverse product dependencies, render warehouse hotspots, and draft a governed transfer action inside Gemini Enterprise.

By Paul Parkinson · Baseline published August 9, 2026

This project turns one supply-chain question into a coordinated A2A workflow. An inventory gateway routes natural-language requests to Oracle-backed specialists for relational risk analysis, SQL property graph traversal, spatial hotspot rendering, and approval-gated inventory actions. The runtime is deployed on the existing Google Cloud VM beside the original demo service, while paulparkdb remains the private, authoritative data plane.

The important architectural boundary is that A2A transports agent requests and results; it does not move the system of record into the model. Oracle AI Database owns the data, relationships, coordinates, and Select AI metadata. The Java service turns those governed results into A2A messages and PNG artifacts that Gemini Enterprise can display inline.

All implementation code, SQL, systemd units, agent cards, and the exact deployment runbook are in the project source directory.

The Four-Prompt Supply-Chain Flow

The target interaction follows the public demo flow while using deterministic synthetic data owned by this environment:

  1. “Which products are at risk of stockouts next quarter, and which regions are driving that risk?”
  2. “Which upstream suppliers and downstream warehouses are connected to SKU-500?”
  3. “Show SKU-500 stockout hotspots on a map.”
  4. “Suggest actions to reduce the stockout risk for SKU-500.”
Gemini Enterprise → inventory-system router → Oracle inventory analysis → graph specialist → spatial specialist → inventory-action coordinator → text + structured data + PNG artifacts

The current risk query identifies SKU-500 as the highest-risk product, driven by the Northeast corridor. The graph path connects Vertex Plastics through Columbus Final Pack and the Port of Houston to Newark Inventory Hub. The spatial agent identifies Newark as the primary pressure node and DFW as the relief source. The action coordinator drafts a 500-unit DFW-to-Newark transfer but explicitly returns PENDING_APPROVAL and NOT_EXECUTED.

One Runtime, Several A2A Agent Surfaces

Inventory System Router

Classifies inventory, graph, spatial, and action intent. It delegates general inventory questions to the managed Oracle agent when OAuth is available and otherwise uses the local Oracle SQL fallback.

Graph Specialist

Queries SUPPLY_CHAIN_GRAPH with SQL/PGQ when available and uses equivalent relational joins as a visible fallback. It returns the dependency explanation and a deterministic PNG.

Spatial Specialist

Combines warehouse coordinates with per-product hotspot metrics and renders a map artifact from database-backed data.

Inventory Action Coordinator

Combines risk, graph, and spatial evidence into a draft action. The reference implementation never converts the recommendation into an automatic database write.

Select AI Specialist

Targets a narrow PAULPARK_SUPPLY_CHAIN_DEMO profile. Until the provider credential is installed, inventory analysis uses explicit SQL over the same allowlisted demo objects.

Oracle AI Database Agent

The planned Marketplace agent authenticates each end user with Oracle database identity over OAuth and invokes the in-database DBMS_CLOUD_AI_AGENT team.

Each live card advertises A2A protocol version 0.3.0, JSON-RPC transport, text input, and the output modes appropriate to that specialist. The graph and spatial cards advertise image/png so Gemini Enterprise can render their deterministic artifacts inline.

Model Risk, Geography, and Topology in One Oracle Database

The demo schema intentionally separates primary entities, graph edges, risk summaries, and spatial attributes. This keeps each tool narrow while still allowing Oracle AI Database to answer cross-domain questions without copying data to a separate graph or geospatial store.

Quarter-level product risk

CREATE TABLE sc_inventory_risk_summary (
    product_id                   VARCHAR2(40) PRIMARY KEY
        REFERENCES sc_products (product_id),
    quarter_label                VARCHAR2(30) NOT NULL,
    risk_level                   VARCHAR2(20) NOT NULL,
    stockout_probability         NUMBER(6,4) NOT NULL,
    at_risk_units                NUMBER(12),
    projected_revenue_impact_usd NUMBER(14,2),
    primary_region               VARCHAR2(100),
    recommendation_summary       VARCHAR2(4000),
    active_flag                  CHAR(1) DEFAULT 'Y' NOT NULL
);

Warehouse hotspot and spatial attributes

CREATE TABLE sc_warehouse_risk_snapshot (
    snapshot_id       NUMBER GENERATED BY DEFAULT AS IDENTITY PRIMARY KEY,
    product_id        VARCHAR2(40) REFERENCES sc_products,
    warehouse_id      NUMBER REFERENCES sc_warehouses,
    hotspot_rank      NUMBER(3) NOT NULL,
    hotspot_score     NUMBER(6,4) NOT NULL,
    coverage_days     NUMBER(6,2),
    backlog_units     NUMBER(12),
    at_risk_units     NUMBER(12),
    revenue_impact_usd NUMBER(14,2),
    risk_level        VARCHAR2(20) NOT NULL,
    recommended_role  VARCHAR2(30) NOT NULL
);

CREATE TABLE sc_warehouse_geo (
    warehouse_id   NUMBER PRIMARY KEY REFERENCES sc_warehouses,
    warehouse_code VARCHAR2(30) NOT NULL,
    county_name    VARCHAR2(100) NOT NULL,
    state_code     VARCHAR2(10) NOT NULL,
    region_name    VARCHAR2(100) NOT NULL,
    latitude       NUMBER(9,6) NOT NULL,
    longitude      NUMBER(9,6) NOT NULL
);

Oracle SQL property graph projection

CREATE PROPERTY GRAPH supply_chain_graph
  VERTEX TABLES (
    sc_suppliers   KEY (supplier_id)  LABEL supplier,
    sc_plants      KEY (plant_id)     LABEL plant,
    sc_ports       KEY (port_id)      LABEL port,
    sc_warehouses  KEY (warehouse_id) LABEL warehouse,
    sc_products    KEY (product_id)   LABEL product,
    sc_alerts      KEY (alert_id)     LABEL alert
  )
  EDGE TABLES (
    sc_supplier_plant    SOURCE KEY (supplier_id)  REFERENCES sc_suppliers
                         DESTINATION KEY (plant_id) REFERENCES sc_plants,
    sc_plant_port        SOURCE KEY (plant_id)     REFERENCES sc_plants
                         DESTINATION KEY (port_id)  REFERENCES sc_ports,
    sc_port_warehouse    SOURCE KEY (port_id)      REFERENCES sc_ports
                         DESTINATION KEY (warehouse_id) REFERENCES sc_warehouses,
    sc_warehouse_product SOURCE KEY (warehouse_id) REFERENCES sc_warehouses
                         DESTINATION KEY (product_id) REFERENCES sc_products,
    sc_alert_port        SOURCE KEY (alert_id)     REFERENCES sc_alerts
                         DESTINATION KEY (port_id)  REFERENCES sc_ports
  )
  OPTIONS (TRUSTED MODE);

The relational tables and seed data are installed. The Java agent first attempts SQL/PGQ and, if the property graph is not yet present, executes the equivalent relational joins and labels the response database-relational-fallback. The ADMIN preparation script grants only CREATE PROPERTY GRAPH and execute on the two Select AI packages to FINANCIAL.

Keep the Select AI Boundary Narrow

The prepared PAULPARK_SUPPLY_CHAIN_DEMO profile names only the tables, view, and property graph shown above. It does not expose the complete FINANCIAL or ADMIN schema.

DBMS_CLOUD_AI.CREATE_PROFILE(
  profile_name => 'PAULPARK_SUPPLY_CHAIN_DEMO',
  attributes   => JSON_OBJECT(
    'provider'        VALUE 'google',
    'credential_name' VALUE 'GOOGLE_AI_CRED',
    'model'           VALUE 'gemini-2.5-flash',
    'object_list'     VALUE JSON_ARRAY(
      JSON_OBJECT('owner' VALUE 'FINANCIAL', 'name' VALUE 'SC_PRODUCTS'),
      JSON_OBJECT('owner' VALUE 'FINANCIAL', 'name' VALUE 'SC_WAREHOUSES'),
      JSON_OBJECT('owner' VALUE 'FINANCIAL', 'name' VALUE 'SC_INVENTORY_RISK_DEMO_V'),
      JSON_OBJECT('owner' VALUE 'FINANCIAL', 'name' VALUE 'SUPPLY_CHAIN_GRAPH')
    )
  )
);

The repository includes the full object list, a hidden-input credential script, and a showsql verification query. It also pins Oracle’s official Marketplace agent installer scripts to a known Git commit and verifies their SHA-256 digests before use.

Current blocker: opening Google AI Studio as paul.parkinson@oracle.com returns “Service Not Allowed.” This means the Workspace organization has disabled AI Studio for the account. The preferred resolution is for the Workspace administrator to enable Google AI Studio for the user or organizational unit. A Cloud Console API key restricted to the Generative Language API may be another short-term route if organization policy permits it, but Google is moving Gemini API traffic to service-account-bound authorization keys; the durable choice should be agreed with the organization administrator.

The Oracle AI Database Agent is not coupled to Google as its Select AI model provider. If organizational policy intentionally forbids AI Studio, the profile can instead use another Oracle-supported provider—such as OCI Generative AI, OpenAI, or Anthropic—without changing the A2A agent topology.

Add the Managed Oracle AI Database Agent

The managed path complements the custom specialists. Gemini Enterprise supplies the user experience and agent invocation; Oracle performs NL2SQL and SQL execution under the user’s own database identity.

  1. Enable the database A2A server with the documented adb$feature free-form tag.
  2. Register an OAuth client against the database registration endpoint using ADMIN and the Gemini redirect URI https://vertexaisearch.cloud.google.com/oauth-redirect.
  3. Create and verify the narrow Select AI profile as FINANCIAL.
  4. Run Oracle’s official oracle_ai_database_agent_tool.sql and oracle_ai_database_agent.sql installers.
  5. Add the Oracle AI Database Agent from Google Cloud Marketplace and grant intended users Agent User access.
  6. In Gemini Enterprise, authorize with the individual Oracle database username and password—not Google or OCI credentials.

Identity boundary: Gemini Enterprise does not grant extra database privileges. Oracle OAuth establishes the individual database identity, and the Select AI profile plus normal Oracle grants define the accessible data surface.

Deploy Beside Existing Workloads Without Resizing the VM

The target environment already contained a Java service on port 443. Capacity checks showed approximately 2.9 GiB of available memory and 60 GiB of free disk, so a second VM was unnecessary. The new service is isolated under /opt/oracle-gemini-supply-chain-a2a and managed by its own systemd unit with a 1.4 GiB memory ceiling.

Security and Governance Choices

  • Secrets live only in ignored local files or protected root-owned VM configuration; no credential value is present in the repository.
  • The demo application connects as FINANCIAL, while ADMIN is reserved for narrow one-time grants, A2A registration, and official installer operations.
  • The Select AI profile uses an explicit object list rather than schema-wide exposure.
  • The custom action agent creates a draft and requires approval; it does not silently execute a transfer.
  • The public rule exposes only the required A2A TLS port on one uniquely tagged VM.
  • Fallback modes identify themselves in response metadata so operators can distinguish SQL/PGQ, relational, Select AI, and deterministic execution.
